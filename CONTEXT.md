# CONTEXT.md

Glossary for this repo. Terms are added as they resolve in conversation; no implementation detail lives here.

## Terms

- **Capture** — a SingleFile snapshot of a live flocksafety.com page; the ground truth the Recreation reproduces. There is one: the 2026-09-12 run, taken with the flag set recorded under [The snapshot](README.md#the-snapshot).
- **Capture list** — the frozen page listing `regression/capture-list-2026-09-12.txt` (1,200 URLs), the record the 2026-09-12 capture run left of what upstream held; the serving check's count invariant and the **upstream watch**'s frozen comparison both read it. Its companion is the watch's *moving* reference, the **upstream baseline**.
- **Frozen snapshot** — the Recreation reproduces flocksafety.com as it stood on 2026-09-12 and does not follow the live site. `served/` is committed and *is* the artifact; nothing in the repo reaches upstream to re-derive it — the only upstream-facing tool is the **upstream watch**, which reads and reports but never writes the tree. _Avoid_: point-in-time snapshot.
- **Refresh workflow** (retired) — the process that kept the Recreation synced to the live site by re-inventorying it, diffing the drift, and re-capturing what changed, plus the upstream video-liveness probe. It was retired when the snapshot was declared final; its tools and runbook are in git history only.
- **Upstream watch** — the hand-run command `npm run upstream` (the pure cores `regression/upstream-watch.mjs`, `upstream-baseline.mjs`, `upstream-copy.mjs`, `upstream-chrome.mjs`, `upstream-assets.mjs` and `upstream-media.mjs`, plus their thin network edge `upstream-watch-cli.mjs`) that reports whether the live site still matches the tree we serve and what has moved since we last looked, without re-capturing, rebuilding, or editing the tree. It is the one deliberate exception to "nothing reaches upstream": it reads upstream, writes only its **upstream baseline** and its own `--out` evidence, and never writes `served/`.
- **Watched universe** — the set of URLs one watch run probes: the union of the sitemap's `<loc>` paths, the homepage's same-origin anchor paths, and the **Capture list**. Sitemap membership is a per-URL field, never the universe's boundary, because each source is blind in a different direction.
- **Upstream baseline** — the committed state `regression/upstream-baseline.json`: one row per watched URL (path, sitemap membership, status, redirect target, and the projection digests), the digests of the site's shared asset set, plus the **verified-in-sync date**. It is the moving reference every run after the first diffs against, and only an explicit `--accept` rewrites it, so a check can never silently move its own reference point.
- **Silent baseline** — the **upstream watch**'s first run, which has no **upstream baseline** to diff against: it records one and reports no baseline delta (the `since` section and the restyle comparison are empty), so the whole watched universe never registers as a change on the first run. The tiers that compare live against the **Capture list** or the served tree rather than against the empty baseline — index, **copy projection**, **chrome projection** and **media liveness** — still report.
- **Verified-in-sync date** — the date the last run recorded in the **upstream baseline**, the day upstream was last confirmed to match what we hold; the repo states it beside the snapshot's provenance. It is a fact about when we last looked, not a claim about what changed before.
- **Copy projection** — a page's prose as the Recreation reproduces it: the text of its headings, paragraphs, list items and blockquotes, one run per block, entities decoded and whitespace collapsed. Compared live-versus-served it is a hard finding, because the tree is meant to carry the same words. Runtime-filled regions (Webflow's table of contents, Finsweet's filter empty state, the ATS-backed jobs list, the Wistia player) are excluded: the Capture froze them filled, and the raw live page the watch fetches carries a template. The 2026-09-13 measurement compared 1,181 served pages and found two real copy edits and nothing else.
- **Chrome projection** — a page's nav, footer and global chrome text, extracted separately from the **copy projection** because the tree stripped exactly the regions upstream still carries (the sign-in link, the chat launcher, the OneTrust stack, the Qualified offer). Compared live-versus-served it is a soft finding, reported against an allow-list named after the strip table's targets; ticket 04 sets that allow-list from ticket 03's measurement, and the live page's masked chrome digest joins the **upstream baseline** row in ticket 05. Ticket 04b adds a second, chrome-only list of **runtime-fill exclusions** stripped from both sides, so a rendered capture's script-filled regions stop reading as drift.
- **Runtime-fill exclusion** — a region a page's own scripts populate at render time, present in the rendered **Capture** and absent (or in a different order) in the raw live fetch. They live beside the allow-list as `regression/upstream-chrome.mjs`'s `CHROME_RUNTIME_FILL` and are stripped from *both* sides of the **chrome projection** (the filled side is our own); they are deliberately not folded into the copy tier's `isGenerated`, because the Finsweet CMS list carries prose the **copy projection** must keep reading. Each entry records what it still cannot see. _Avoid_: generated region (a broader, shared notion that also feeds the copy tier).
- **Restyle signal** — the content digest of the site's shared stylesheet and script set, discovered from a live page's own Webflow site-directory references and recorded in the **upstream baseline**. Because the digest is over the assets' bytes and never their URLs, a publish that changes a build-hashed filename alone is not a finding; a digest the baseline does not hold is a chrome-tier finding naming the asset and its size, because a global restyle changes no page's text. It cannot see an asset the one discovered page does not reference, or one reached only from CSS.
- **Demotion** — a watched URL the sitemap still advertises that now answers 3xx; reported with its redirect target as context (usually confirming our own redirect table), never as a finding.
- **Watch probe** — one HTTP status request the watch makes for a watched URL, kept deliberately distinct from ticket 06's **media liveness** probe (which asks a media host about a **media slot**, not a page).
- **Recreation** — the word-for-word, CSS-exact, function-by-function rebuild of flocksafety.com as a Next.js app; the art piece's first milestone. The user's phrase: "EXACT recreation".
- **Parody layer** — the reserved seam where the Recreation will later diverge into the art piece; deliberately unspecified until its own effort.
- **Story-hook seam** (dormant) — the injected runtime every served page carries that exposes `window.flockParody.apply(patches)` (selector + `text`/`html`/`src`/`style` patches, queued until the document is ready): the **Parody layer**'s integration point for dialogue-driven DOM patches. Nothing calls it today — it ships so the Parody layer has a landed contract to drive, and its rule is DOM-only: a patch may change text or a source, never add network behavior. Contract and rationale: `pipeline/story-hook.js`.
- **Chat mimic** — the cloned chat assistant (the real site's is Qualified), powered by a yarnspinner-ts wrapper instead of a live backend. Yarn script content is a separate future effort written by the user.
- **Link policy** — captured internal links repoint at Recreation routes; external links remain untouched.
- **Injected layer** — one of the seven groups of bytes the Recreation injects into served pages: six site-wide (`motion`, `interactions`, `nav`, `chat`, `story-hook`, `scroll`) and one page-scoped (`legibility`, `/safe-cities` only). Every style/script an injected layer carries is marked `data-flock-parody="<layer>"`, which is how the strip audit tells the Recreation's own bytes from the Capture's; a layer's delivery form (an asset-backed file, an inline body, or no style at all) is part of its identity, not an accident. _Avoid_: runtime, script, bundle.
- **Reduced-motion promise** — the rule that with reduced motion requested, and with no JavaScript at all, every served page lands on the same static end-state and every widget still works. It is a promise about **capture-derived** animation: the Chat mimic is mimic-owned, so it animates regardless. _Avoid_: accessibility mode.
- **Motion layer** — the reveal mimic that restores the Captures' scroll- and load-driven motion: the tree carries every captured animation from-state normalized to its static end-state, and declarative annotations plus one shared CSS/JS pair (injected, never the original runtime) play the reveals one-shot; reduced motion and no-JS both render the static end-state.
- **Interaction layer** — the delegated-click mimic that restores the Captures' tab, dropdown, accordion, and slider behavior: one shared CSS/JS pair (injected, never the original Webflow/Swiper/GSAP runtimes) operates the captured classes and geometry from a single document listener, with zero per-page bespoke logic; reduced motion degrades every animation to instant function, never to a broken widget.
- **From-state / end-state** — an element's captured pre-animation style (e.g. inline `opacity:0`, blurred split words) versus its final static look; the tree carries the former normalized to the latter, and the motion layer re-applies from-states only while animating.
- **Serving check** — the full-scale HTTP check (`npm run routes`) that the serving layer does its job: every live page 200, every legacy redirect stub 301 to its local target, every dead collection root / auth-gated stub / dropped scaffold-test page 404, the count identity (served + dropped accounts for every page the capture run listed), the site-wide strip audit (zero tracker residue, no capture-derived executable script, **no frame pointed outside the media allow-list**, **no executable script inside a `srcdoc` payload**, and **no remote reference outside a class the media allow-list accepts as inert**), and **byte-identity** — every served page's body must equal the file in the tree, and every asset named in `served/assets.json` — every **Extracted asset** and every **Deduped body** — must answer at its content-addressed path with the content type its extension declares and the same bytes as the file on disk. Same bytes ⇒ same pixels, so byte-identity is the serving layer's whole guarantee; there is no pixel gate (the retired ticket-06 harness compared the served tree against itself).
- **Strip decision** — what the strip pass removed from each Capture (Qualified offer host and header-height var, the chat launcher, the OneTrust consent stack, the account/auth Sign In chrome), recorded per page in `served/build-log.json` with removed byte counts; the human side-by-side at the phase gates reviews the visual result.
- **Video slot** — a captured video embed. A Capture cannot play a video, so it keeps an inert snapshot of the player instead — an inlined `srcdoc` player document, the JS-built player chrome (poster + play button), or a `<wistia-player>` web component with a declarative shadow root — and the built tree carries the live player the page's own `w-json-ld` names as `embedUrl` in place of that snapshot, keeping the slot element and its box. The live `popover` slots are inlined the same way (their box was already the captured 16:9 padding box); the YouTube `data-video-id` panels stay `src`-less until the interactions runtime arms them on the poster click; medias that are dead upstream, and the hidden Vidzflow video.js documents (stripped, not played), do not become live.
- **Media allow-list** — the hosts a served page's frames may name (`pipeline/audit.mjs`, currently `fast.wistia.net`, `www.youtube.com` and `www.youtube-nocookie.com`): the whole of the exception to the zero-outbound rule, enforced by the strip audit rather than by construction. `pipeline/audit.mjs` owns the whole invariant — the residue classes, the script census, and the allow-list — as `audit(pageHtml) → findings`, and the serving check calls the same module on the served bytes. It counts the **absolute `<iframe src>` values** it can see, looks **inside `srcdoc` payloads** (`srcdoc scripts` — an executable script there fails the invariant), and counts any **remote reference outside a known class** (`unclassified remote refs`); the classes it accepts as inert (a `poster=`, a Lottie `data-src`, a CSS `url()`, metadata, JSON-LD, an allow-listed frame) are accepted because the captured `img-src 'self' data:` already refuses them.
- **Media slot** — an allow-listed `<iframe src>` a served page carries, parsed to its provider and media id (`regression/upstream-media.mjs`): `wistia:<id>` for `fast.wistia.net/embed/iframe/<id>`, `youtube:<id>` for `www.youtube.com` or `www.youtube-nocookie.com` `/embed/<id>` (the two hosts share one key, so a video is probed once). It is the census the **media liveness** check runs over, taken from the served bytes and not a hand-listed inventory; the tree as captured on 2026-09-12 held 217 slots across 162 pages. It does not include the `srcdoc` snapshots, the `data-video-id` panels, or `<video>` tags — those never reach the network as an allow-listed frame.
- **Media liveness** — one of the upstream watch's checks: every **media slot** the tree serves is asked through its media host's own metadata (Wistia's `fast.wistia.com/embed/medias/<id>.json`, YouTube's oEmbed) and classified `alive`, `gone` (a 404, or a Wistia media that is not ready or has no delivery asset) or `restricted` (YouTube 401 private / 403 embed-disabled). A slot that is not alive is a finding naming the page and the slot, beside the index, copy and chrome findings in the one report; a status the rule cannot classify is an operational failure, never mass-dead media. It cannot see a media that resolves but refuses to play behind that metadata (a delivery stream that 403s, a geo-block), and it sees only allow-listed `<iframe src>` slots.
- **Extracted asset** — a Capture's inlined `data:` URI (image, font, sound) carried by the tree as one content-addressed file, `/assets/<sha16>.<ext>`, and referenced from every page that carried it; the same bytes are stored once instead of re-encoded per page. Same-origin, so the zero-outbound invariant is untouched by it.
- **Deduped body** — a page's `<style>` or `<script>` body of at least 1 KB, carried by the tree as one content-addressed file (`/assets/<sha16>.css|.js`) with a `<link>` or `<script src>` left in the position the body held, so the stylesheets a Capture re-encodes on all 1,181 pages are stored (and transferred) once; the same content-addressing an **Extracted asset** uses, with the page's own `style-src`/`script-src` widened by exactly `'self'` to load it. Bodies under 1 KB and non-JavaScript scripts stay inline.
- **Email gate** — the Chat mimic's demo-branch stop: the pinned demo-ask reply followed by a single "Maybe later" option that returns to the hub option set. Nothing is captured or submitted, and no divergence notice is rendered; the intentional stop is stated only in `dialogue/flock.yarn`.
- **Hub option set** — the shared choice set (help / Get a Demo / Support) re-offered to the visitor without repeating the greeting. The email gate returns here, so the conversation never dead-ends.
