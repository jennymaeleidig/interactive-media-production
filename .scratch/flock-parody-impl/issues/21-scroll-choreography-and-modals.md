# 21: scroll choreography and modals

**What to build:** The `/safe-cities` page's scroll-driven behavior and its
"see it in action" modal, which the Capture strips (the live page drives them
with inline GSAP/ScrollTrigger scripts and Webflow's IX2 data). A vanilla
runtime — no GSAP, no CDN, so the zero-outbound invariant holds — restores:

- `[animate="scrub-word"]` headings: each word runs the captured color
  sequence dark → green → near-white as the heading scrolls in, reversing when
  it scrolls back out.
- `.line-label` / `.line-label--marker`: the badge pill scales `0 → 1` and its
  marker slides up `170% → 0` on scroll-in.
- `[data-scroll-video]`: play at `top 45%`, pause at `bottom 20%`.
- `#stickme`: the sticky "see it in action" button pins to the viewport bottom
  and releases at its parent's end (`.stick` / `.stick--is-stuck`).
- `#main-progress` / `.main-line`: the page's SVG route draws as it scrolls.
- `.c-modal` dialogs: `data-c-modal-open="<id>"` opens
  `dialog[data-c-modal="<id>"]`; `[c-modal-close]`, backdrop, and Escape close
  it. Opening runs the modal's own route draw (`#route-progress` scrubbed on
  `[c-modal-scroll]`), and each `.marker[data-stop]` is placed along the path
  opposite its timeline event and pops in as that event scrolls into view.

Every behavior keys on captured attributes/classes (no per-page logic), so the
layer covers any page carrying them. The build normalizes the captured
from-states to their end-states first, so a JavaScript-disabled or
reduced-motion page renders the settled layout — which also folds the
`/safe-cities` scrub-word white override into the animation itself (the
dark-subhead contrast fix stays).
